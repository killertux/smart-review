# IR-18 test and smoke coverage

> Historical measurement and migration record. Current commands and policy live in
> [`../testing.md`](../testing.md).

IR-18 keeps behavioural confidence in deterministic Rust tests and reserves live
terminal/process execution for a small named smoke suite. The historical broad feature
validators remain available as an opt-in migration oracle, but they are not the default gate.

## Commands

```sh
# Complete default gate: format, lint, deterministic tests, build and named smoke.
scripts/validate/all.sh

# Named smoke only, using an already-built target/debug/smart-review.
scripts/validate/all.sh --smoke-only

# Historical broad validators, retained temporarily as a migration oracle.
SMART_REVIEW_FULL_VALIDATION=1 scripts/validate/all.sh
```

`cargo test --all-features` uses no network, account, credential or user repository.
The smoke suite uses only temporary repositories, fake `gh` executables and loopback
HTTP servers. Live provider/catalog checks remain separately enabled with
`SMART_REVIEW_LIVE_TESTS=1`; they are read-only unless an owner deliberately supplies a
sandbox target to a standalone validator.

`tui::test_support::Scenario` is the minimal composed runner. It sends decoded events
through the real reducer and production effect-to-job router, lets a fake adapter
boundary answer the concrete job, holds those completions for deliberate release order,
and renders through `TestBackend`. State assertions remain alongside frame assertions
so a test cannot pass on a header alone.

## Named wiring smoke contracts

| Contract | Validator | Wiring retained |
|---|---|---|
| Startup/restore and resize | `shell.sh --smoke-only` | Terminal takeover/restore, persisted theme reload, SIGWINCH, clean quit |
| Key and mouse decoding | `pull-requests.sh --smoke-only` | Command key opens a review; SGR click selects the intended file |
| Remote to local | `workspace-models.sh --smoke-only` | Fake forge ref becomes an app-owned worktree and visible local diff without moving the checkout |
| Provider stream/cancel | `chat.sh --smoke-only` | Loopback streaming request, visible partial answer, cancellation and durable partial transcript |
| Publish payload | `review-publishing.sh --smoke-only` | Immutable preview followed by exactly one fake-`gh` mutation with the confirmed payload |
| Reply/dry-run/editor | `review-collaboration.sh --smoke-only` | Reply routing, terminal suspension/restoration, and zero dispatches with complete dry-run records |

All waits are screen or durable-state postconditions. `drive.py` rejects unmatched
ready/step/resize conditions, unexpected exits, mismatched key/wait counts and global
deadlines; there are no broad fixed sleeps.

## Migration and measurements

The historical seven-validator run remains behind `SMART_REVIEW_FULL_VALIDATION=1` so a
replacement assertion can be compared before deletion. The default removes repeated
analysis, model-picker, browsing, publishing and collaboration PTY journeys already
covered by the catalog above.

Reference measurement on 2026-09-21 (Apple M1 Pro, warm debug build):

| Stage | Before | IR-18 |
|---|---:|---:|
| Broad validator wall time (`--scenarios-only`) | 34.9 s | retained opt-in |
| Named smoke wall time (`--smoke-only`) | n/a | 9.6 s |
| Rust test command wall time | 11.6 s | 11.3 s |
| Rust test body reported time | 10.4 s | 10.4 s |

The Rust stage remains above the aspirational five-second warm target. Isolation by
module found the fake-`gh` process adapter contracts dominate at about nine seconds;
domain, application and TUI groups each complete below one second. They remain in the
default suite for now because retiring those payload/error contracts without equivalent
coverage would trade confidence for a timing number. CI summaries record the Rust and
per-smoke stage timings so this bottleneck stays visible.
