# IR-17 runtime and context performance

This is the reproducible measurement record for IR-17. Run:

```sh
scripts/performance/ir-17.sh
```

The runner uses release-mode ignored workloads, runs them serially, prints machine and
toolchain identity, reports p50/p95 timings, and wraps the process with the platform's
resource timer. It then runs the deterministic IR-17 contracts in the warm debug profile.
Compiler time and memory are not workload measurements; warm the build before recording
the resource-timer result.

## Reference machine

- MacBook Air `Mac17,3`, Apple M5, 10 cores, 16 GB RAM
- macOS/Darwin 25.5.0, arm64
- `rustc 1.95.0 (59807616e 2026-04-14)` / Cargo 1.95.0
- Baseline revision: `72f9084` (merged IR-16)
- Measurement date: 2026-09-21

## Before baseline

The release baseline was captured before implementation with a 400-file/9,600-changed-
line `TestBackend` workload. It reported 1,409 µs parse+prepare, 374 µs first draw,
140 µs navigation draw p50 and 151 µs p95. The original navigation timer did not include
the reducer call, so it is retained as context rather than presented as an exact speedup.
The warmed test process reached 95,698,944 bytes maximum RSS (the harness, not only the
view).

Source-level deterministic baselines explain the other hotspots: an idle wake rendered
twice; background progress could wait for the 250 ms idle poll or a longer key-prefix
deadline; and a 400-file modified patch required 803 `git show` processes (old and new
representations plus three convention probes). Long-chat and streamed-analysis timings
were not instrumented before IR-17, so no numeric before/after claim is made for them.

## After result

Warm serial release run:

| Workload | Result |
|---|---:|
| 400 files / 9,600 changed lines | prepare 1,459 µs off-loop; first draw 341 µs |
| Diff navigation reducer + draw | p50 149 µs; p95 161 µs (300 frames) |
| Diff drawable projection | 1,978,184 bytes; split duplicate absent while unified |
| Long-line Unicode split view | 449,487 source bytes; prepare 651 µs; draw p95 338 µs |
| Dense discussions and drafts | 1,000 each; prepare 1,332 µs; first draw 431 µs |
| 480-message / 922,210-byte chat | cold visible layout 61 µs; warm p50 6 µs; p95 8 µs |
| Chat layout retained for viewport | 1 message layout / 3,605 text bytes |
| 55,550-byte streamed analysis | 434 deltas in 2,437 µs; stream capped at 64 KiB |
| 400-file context fixture | 4,638 µs; two revision batches / four `cat-file` processes; ignore probes separate |
| Context retained source / bundle | 8,075 / 38,166 bytes under a 40,000-byte per-revision cap |
| Four jobs + 20 rapid replacements | 42 ms; zero stale pages |
| Warm runner maximum RSS | 96,190,464 bytes (91.7 MiB), including the test harness |
| Idle frame requests | one initial frame, then zero for 1,000 unchanged wakes |
| Active background poll cap | 32 ms, including while a key prefix is pending |

Warm debug behavior on the same machine remained suitable for development: large-diff
input-to-frame p95 was 304 µs, long-chat warm-layout p95 was 34 µs, streamed preview
processing took 19.7 ms total, and the context fixture took 26.8 ms.

The measured navigation path is far below the 50 ms event-loop budget and the 30 fps
continuous-rendering budget. The prepared local fixture is usable in about 1.8 ms after
its bytes are available; network checkout and Git setup remain separately timed jobs.
The 91.7 MiB process result remains below the roughly 300 MiB large-PR target.

## Correctness boundaries

- The UI thread still owns terminal drawing and state reduction; workers prepare only
  immutable diff projections.
- A reducer pass is drawn before another input is read, preserving publish/chat
  confirmation visibility.
- Chat follows a stream only while the user remains at the tail.
- Git first batches object metadata, rejects non-blobs/oversized objects, then buffers a
  bounded content batch. No unbounded parallel `git show` fallback exists.
- Context and stream buffers, split rows and chat layout entries all have explicit caps.
- Job timing records contain ids, kinds, durations, outcomes and counts, never contents.
